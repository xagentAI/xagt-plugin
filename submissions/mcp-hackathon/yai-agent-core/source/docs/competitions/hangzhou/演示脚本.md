## 2. POST 预算核对（限流 30 次/分钟/IP）

- 主时间轴**在线** POST：1:30 段 0 次（GET）；1:30–3:00 第 1 次（笔记统计）；3:00–3:40 为**本地运行**（host_c，不占在线额度）；3:40–4:20 第 2 次（MCP）；合计在线 **2 次**，远低于阈值。
- host_c 段为本地进程（`examples/host_c_companion/run.py`），消耗的是本地 .env 的模型额度，与在线限流无关；若时间紧，该段可整段删（属泛化佐证，非主链路）。
- 若录制失误重拍：在线 POST 每分钟不超过 30 次即可；被限流会收到 429 + `Retry-After`，等 60 秒再录。
- GET（/health、/v1/tools、部署证明）不受限流影响，可随意刷新。

## 3. 冷启动与保活预案

- 每段录制开始前 1 分钟先 curl 一次 /health 预热；
- 仓库已配 keepwarm 工作流（每 10 分钟自动 GET /health），评审/录制窗口实例通常是热的；
- 若 POST 超 60 秒无响应：实例正在冷启动，等 1 分钟重试，不要连点（连点会浪费限流额度）。
