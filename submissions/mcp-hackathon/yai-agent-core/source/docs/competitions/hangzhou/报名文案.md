## 3. 作品介绍 / 项目概述

### 3.1 短版（约 300 字，适合"作品简介"类字段）

YAI 数字员工解决一个被多数 Agent 产品忽略的问题：软件厂商想让自己的现有软件拥有 Agent 能力，仍然要自己接模型、写工具总线、写 Agent 循环、写记忆、做适配，门槛高且重复造轮子。YAI 反转范式——宿主软件只负责"声明能力"（普通业务函数加类型注解与 docstring），YAI 内核在进程内自适应完成其余全部：LLM 路由在 direct/react/plan/clarify 四种策略间选择（模型不可用时规则兜底，全程事件可审计），ReAct 循环经 JSON Schema 校验与权限白名单后调用本地函数、MCP Server 远程工具或 OpenAPI 服务工具，结果回灌后由模型收尾交付；记忆层支持 SQLite 持久化与条数/TTL 保留策略。内核本体零第三方运行时硬依赖，模型经 OpenAI 兼容协议可替换（当前演示用 DeepSeek）。作品已 Docker 部署上线、具备免登录在线 API，仓库含 4 个不同行业形态的宿主示例证明"同一内核换宿主即换岗位"，并配 125 项离线测试与 CI 四版本矩阵。

### 3.2 长版（约 800 字，适合"项目详细介绍/创意描述"字段；含大模型环节，满足评分硬要求）

**痛点与创意。** 当下 Agent 领域的多数成果是独立应用或编排框架，软件厂商想让"自己已有的软件"获得 Agent 能力，仍要自行集成模型、工具总线、执行循环、记忆与权限体系。YAI 数字员工（内核名 YAI Agent Core）给出另一条路径：做一颗可内嵌的自适应内核，宿主只声明能力，内核适配宿主，而非宿主改造自己去适配框架。接入成本为一行 `AgentCore.auto(capabilities, model)`，capabilities 就是普通 Python 函数。

**大模型环节全链路（4 个调用点，全程可审计）。** ① 路由分类：每个任务先经一次轻量 LLM 分类，输出策略（direct 直接回答 / react 工具循环 / plan 先规划后执行 / clarify 反问澄清）、模型档位与中文理由；模型异常或输出非法时自动回退确定性规则路由，决策来源随事件流出。② 计划生成：仅 plan 策略触发，模型把任务拆为 2–5 个有序步骤并发 `plan_created` 事件。③ ReAct 推理与工具选择：模型在上下文中选择工具并产出参数，内核做 JSON Schema 校验、allowlist 权限检查后执行；工具来源三类同构——宿主本地函数、MCP Server 远程工具（官方 SDK，支持 Streamable HTTP/stdio/进程内三传输，在线实例已真实接入 DeepWiki）、OpenAPI spec 自动桥接工具。④ 收尾汇总：模型基于完整工具观察链产出可交付的最终结果。所有自适应决策经唯一事件出口 `astream` 以类型化事件流式发出，无静默决策。

**工程与落地。** 内核本体零第三方运行时硬依赖（模型客户端、FastAPI、MCP、HTTP 全部为可选 extra）；四个 SPI 契约（model/channel/memory/policy）支持逐项替换；SQLite 记忆带 scope 隔离、schema 版本钩子与条数/TTL 保留策略；在线服务提供 /health（实时返回 commit）、/v1/tools、POST /v1/agent/run，并实现每 IP 滑动窗口限流。仓库含 4 个宿主示例（办公笔记、销售数据、AI 陪伴、本地 MCP 演示），同一内核不改一行即切换岗位；125 项测试全部离线（假模型/MockTransport/注入时钟，不依赖网络与密钥），GitHub Actions 在 Ubuntu 3.11/3.12/3.13 与 Windows 3.13 四矩阵跑 ruff + pytest。

**演进路线。** 第一阶段作为独立开源内核（本作品）；第二阶段回流内嵌进开源 AI 陪伴项目 AMBRACE，验证真实 To C 软件内嵌路径；第三阶段经 MCP 标准化接入更广生态（已同步投稿 X-Agent MCP Hackathon）。多智能体、向量记忆、工具自生成等在公开路线图中，初赛版本不做宣称。

## 4. 创新点（分条，适合"项目亮点/创新点"字段，4 条）

1. **范式创新：host-declares-capability / core-adapts。** 现有框架止步于提供积木，YAI 让已有软件以零 Agent 代码获得能力，定位是"可内嵌内核"而非又一个 Agent 应用；宿主接入只需一行 auto。
2. **自适应路由可审计、可降级。** LLM 一次性输出策略/档位/理由，每个决策落类型化事件流；模型不可用时规则路由兜底，保证离线、断网、超额场景下的确定性退化。
3. **三源工具同构 + 双协议桥接。** 本地函数、MCP Server、OpenAPI 服务在同一注册表/同一权限链/同一事件流中无差别运行，远程 MCP 工具已在线真实跑通。
4. **内核零硬依赖与 SPI 四契约。** 模型、通道、记忆、权限全部面向契约编程，模型厂商可替换（DeepSeek/通义/OpenAI 仅改环境变量），可进程内嵌、可服务化部署。

## 5. 技术方案 / 架构说明（若系统有独立技术字段）

- 分层：宿主声明 capabilities → discovery/introspect 内省为统一 ToolSpec → AdaptiveRouter（LLM 路由 + 规则兜底）→ AgentLoop（direct/react/plan/clarify）→ ToolExecutor（Schema 校验 → allowlist 权限 → 执行/回灌）→ 通道交付（CLI / collect / FastAPI）。
- 大模型：OpenAI 兼容抽象层，当前演示使用 DeepSeek deepseek-chat，切换厂商仅改环境变量；路由用 standard 档、规划用 strong 档，成本与时延可控。
- 记忆：内存态 + SQLite 持久化（opt-in），条数上限与 TTL 按对话轮边界裁剪，不拆散工具调用对。
- 质量：125 项离线测试、ruff、CI 四矩阵、Dockerfile + render.yaml 一键部署、限流与保活工作流。
- 诚实边界（如系统要求"不足与展望"字段直接用）：未做多智能体协作、向量检索/RAG、自进化写工具与内置 UI；在线实例为免费 PaaS（15 分钟休眠、冷启动约 30–90 秒且波动大、临时盘重建清空）；限流不防御伪造 X-Forwarded-For；无账号鉴权（评审免登录调用，鉴权在路线图）。
