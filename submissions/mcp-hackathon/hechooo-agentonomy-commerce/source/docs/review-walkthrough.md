# 两分钟验收演示

项目主张：**让 Agent 在用户授权预算内，可靠地购买服务并取得结果。**
CSV 收支核对是可验证的付费服务实例；核心展示是授权、预算、付款证据、
交付和幂等恢复之间的闭环。

## 演示前

按 [部署文档](deployment.md) 启动本地 review API，并打开
`http://localhost:8080/`。本地公开访客演示必须配置精确的
`AGENTONOMY_DEMO_ORIGIN=http://localhost:8080`；未配置时，
`/demo/session` 和 `/demo/v1/*` 保持关闭。只使用页面自带的合成示例。

展示开始时明确说明：**商家计算经真实 HTTP 完成，结算是模拟的，所有访客
会话都只使用模拟 USDC，不会使用真实资金。** 访客无需注册、输入或获取
review token。浏览器通过 HttpOnly 同站 Cookie 访问 `/demo/session` 和
`/demo/v1/*`；私有机器 API `/v1/*` 仍单独使用 Bearer token。

每个访客会话都有独立的持久预算，初始额度为 1.00 模拟 USDC；每次成功
交付报告消耗 0.30。会话保留 7 天，最多保留 128 个会话，每滚动一分钟
最多创建 10 个新会话。刷新、恢复已有 Cookie 或重放订单都不会充值、重置
预算或创建新的 spending grant。

## 演示步骤

1. **开始访客会话（约 20 秒）**：点击“开始演示”。页面创建当前浏览器的
   访客会话并显示 1.00 模拟 USDC 预算；不会出现 token 输入框，也不会把
   Cookie 返回到页面或 JSON。
2. **报价与购买（约 40 秒）**：使用预填的合成 CSV，点击“锁定报价”，
   再点击“确认购买”。此时只冻结输入和价格，报价有效期 5 分钟。展示
   `delivered`、订单 ID、输入/输出摘要与报告。示例三行中有一行重复，实际
   两笔交易，净额 USD 27.50。核对预算已用 0.30、剩余 0.70、结算次数 1、
   已交付订单 1。
3. **刷新与重放（约 40 秒）**：刷新页面，确认同一访客会话和订单仍可恢复。
   查询原订单或重放同一笔购买，确认结果及计数不变，预算仍为已用 0.30、
   剩余 0.70。不要另建订单来重试未知付款结果。可用第二个浏览器配置文件
   作为 B 访客：B 获得另一份 1.00 预算，不能读取 A 的订单或预览。
4. **边界与证据（约 20 秒）**：展示 `/health` 和版本声明中的完整提交号，
   对照提交源码。说明 `/v1/*` 私有接口仍要求 Bearer token，且其原有持久
   review tenant 与访客沙盒分离；说明跨 Origin、无效 Cookie、超出速率限制
   和不合法 CSV 会被拒绝。所有结算仍是模拟，不把 HTTP 200 或付款成功单独
   当作交付成功。

演示到第三步即可形成一个完整主线。若需要展示超预算，用独立标记的测试状态
执行三笔不同订单，第四笔会进入 `confirmation_required / BUDGET_EXCEEDED`，
不会扣款。不要在主线中重复新建订单来“重试”未知付款结果。

## 范围与边界

| 范围 | 本地演示应展示的边界 |
| --- | --- |
| Core / Marketplace | 使用迁移的真实授权、策略、预算预占、购买状态机和审计实现 |
| 访客会话 | HttpOnly Cookie 只选择隔离的持久访客沙盒；会话本身只保存模拟状态 |
| 服务交付 | 实际 loopback HTTP 请求，校验收据范围与输入摘要，执行 CSV 核对 |
| 结算 | 明示的模拟 RPC 和模拟 USDC；未进行真实资金支付 |
| 恢复 | Core、订单、结果和商家幂等记录持久化；刷新、重启和重放不补充预算 |
| 私有 API | 原有 `/v1/*` Bearer 入口、持久 review tenant 和 verifier 流程保持独立 |
| MCP | 原有 `clink_node` stdio 演示可独立运行；它与本页的 CSV API 不共用状态 |
| 部署 | 提供容器和版本绑定验收脚本；公开 HTTPS 地址仍需实际部署验证 |
| 提交 | 可生成有源码和哈希清单的草稿；不代签权利声明、不声称已获准补交 |

报告保留 7 天；私有 tenant 的初始签名授权 30 天后到期且不自动续签。访客
会话最多保留 7 天，刷新或重放不会获得新的授权。本文描述本地工作树中的
演示边界，不构成新的公网部署、独立浏览器验收或测试通过声明。
