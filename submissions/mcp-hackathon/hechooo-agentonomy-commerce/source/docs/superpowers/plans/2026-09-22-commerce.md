# Agentonomy Commerce Implementation Plan

> **For agentic workers:** Use subagent-driven-development to implement the bounded tasks. Main agent owns integration and final acceptance.

**Goal:** A standalone repository proving that an Agent can discover, buy and receive a useful service within an authorized budget, with safe retry behavior.

**Architecture:** Export the current Clink source without private runtime state. Keep production Core and Marketplace implementations; add an isolated local demo composition with simulated external settlement and a deterministic paid data service. Agent interactions use the unified `clink_node` gateway.

**Tech Stack:** Python 3.11+, FastAPI, MCP, SQLAlchemy/SQLite, Ethereum signature verification; Solidity/Foundry for the existing executor.

## Global Constraints

- Original Clink checkout is read-only for this task.
- The new repository is `HEchooo/agentonomy-commerce`, branch `main`.
- Core owns identity, policy, reservation, settlement and audit.
- Tests never execute real transactions or use production credentials.
- All financial values use Decimal or integer atomic units.
- Copy first-party implementations, not a wrapper around a private API.

## Tasks

- [x] Export source applications, contracts and generic installer assets; exclude runtime state, secrets, private deployment operations and per-user acceptance fixtures.
- [x] Add Commerce composition and tests: successful purchase produces a useful result and decrements real Core budget; repeat execution does not recharge; over-budget preview/execute fails; delivery failure preserves settled payment; terminal replay does not repay; revoked authorization cannot purchase.
- [x] Provide a one-command local demo and MCP entry; label external fixture boundaries in output and documentation.
- [x] Add clean install instructions, a dependency lock, architecture and migration notes, and CI for the shipped source.
- [x] Run local end-to-end acceptance, Core/Marketplace/Node/Hosted regressions and contract tests. Record exact passing/blocked checks.
- [x] Review source export and changes, initialize the independent sibling checkout and run acceptance there. Delivery is recorded by the repository commit and `origin/main`.
